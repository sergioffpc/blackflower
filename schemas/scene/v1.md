# Scene v1

A scene contains only entities. Each entity owns its persistent string identity,
placement transform and optional bounds. Bounds are collision geometry authored
independently of any visual mesh. There are no global collision, light or spawn
collections, participant dimensions or gameplay rules.

## Coordinates and encoding

Coordinates use metres in a right-handed frame: X right, Y up. All integers are
little-endian unsigned values; geometry uses little-endian IEEE 754 binary64.
Rotations are unit quaternions in XYZW order.

The payload starts with a u32 entity count, followed by that many complete
entity records. An empty scene occupies four bytes. No padding or trailing bytes
are permitted. Integer widths define representability; no policy count cap
applies. Consumers allocate only as records are successfully decoded.

Each entity record contains these fields in order:

| Field          | Encoding                             |
| -------------- | ------------------------------------ |
| ID byte length | u32                                  |
| ID             | That many ASCII bytes, no terminator |
| Position       | Three binary64 coordinates           |
| Rotation       | Four binary64 quaternion components  |
| Uniform scale  | One binary64 value                   |
| Bound count    | u32                                  |
| Bounds         | That many bound records              |

IDs match case-sensitive `[A-Za-z0-9][A-Za-z0-9_.:-]*`, are unique within the
scene, and sort in strictly increasing ASCII order. They identify placements
independently of USD prim paths. The fixed portion of an entity record occupies
72 bytes, excluding the ID bytes and bounds.

Each bound starts with a u32 kind. Kind 1 is an oriented box, followed by three
binary64 world-space centre coordinates, three binary64 full dimensions and four
binary64 XYZW rotation components: 84 bytes in total. Other kinds are rejected.
Ownership follows containment in the entity record; no separate owner index or
persistent bound ID is encoded. Bounds sort by their authored child prim names.

Entity transforms describe placement. Bound transforms are already composed into
world space; consumers must not apply the entity transform a second time. All
numeric fields must be finite; dimensions and scale must be positive. Quaternion
squared norm must differ from one by at most 1e-12. The loader validates
identities, transforms, kinds and byte boundaries before exposing a complete
scene. Physical suitability and gameplay remain consumer decisions.

## OpenUSD authoring

The cooker snapshots a scene and its directly referenced entity definition
layers, then composes that private graph through the pinned OpenUSD bindings.
The full [authoring contract and examples](../../docs/usd-authoring.md) define
the supported subset: `/Scene/Entities`, reusable `/Entity` definitions,
explicit placement IDs and independently authored `Bounds` scopes.

An absent Entities scope yields an empty scene; an absent Bounds scope yields an
entity without collision geometry. Visual import is pending. Source USD and
Python are not runtime dependencies.

## Consumer scenes

ServerScene, AgentScene and ClientScene each contain only entities and currently
receive identical scene payloads. The authenticated pack magic selects the
concrete C++ scene type. Each file is complete without other consumer packs.
Visual meshes, materials, textures, audio, lights, spawns and runtime physics
execution are outside this slice.

This development revision replaces the previous primitive layout in place;
regenerate existing packs. Schema versions follow the
[schema versioning policy](../../docs/development-process.md#schema-versioning).
