# Contributing to Blackflower

## Setup

Install rustup, clone the repository, and enable the versioned Git hooks:

```sh
./scripts/setup-git-hooks.sh
```

The pinned toolchain is installed automatically when a Cargo command runs.

## Quality checks

Run the complete local quality gate before pushing:

```sh
./scripts/ci.sh
```

The command checks formatting, runs Clippy for every workspace target, and runs
the complete workspace test suite with the lockfile enforced.

Any lint suppression must be narrow and include a reason. Do not weaken a
workspace-wide lint to accommodate one call site.

## Commit messages

Every commit message must contain exactly one line and follow Conventional
Commits:

```text
<type>(optional-scope): <description>
```

Examples:

```text
feat(server): validate movement commands
fix(prediction): preserve input sequence numbers
test(simulation): cover replay determinism
docs: explain snapshot versioning
```

Use an imperative, lowercase description without a trailing period. The allowed
types are `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`,
`revert`, `style`, and `test`.

Dependabot branches are the only exception to commit-body validation because
their commits are generated by GitHub. Their commit subjects and pull request
titles still use the `chore(deps):` prefix, and they must be squash-merged with a
single-line commit message. Every commit pushed to `main` is still validated.

## Dependencies

Declare every package dependency in the root `[workspace.dependencies]` table
and inherit it from member manifests with `workspace = true`. Keep default
features disabled unless they are explicitly required.

All dependencies must pass the policy in `deny.toml`. New license or source
exceptions must be specific and document their reason.

## Testing expectations

Changes to simulation or networking code should add the narrowest useful tests.
As the corresponding systems are introduced, prioritize:

- deterministic replay tests using identical inputs and seeds;
- client prediction and authoritative convergence tests;
- protocol golden tests for versioned wire representations;
- property tests for parsers, state transitions, and numeric boundaries;
- fuzz targets for untrusted network and content inputs.

Keep authoritative simulation tests independent from rendering, audio, wall
clock time, and unordered collection iteration.
